# 可反哺柚爱本体的通用建议

> 来源：mdtest 项目 UI 整理与 shadcn-svelte 风格回调经验。本文只记录建议，不直接修改 `Agent/skills/pomelosuki/SKILL.md`。

## 1. 项目档案必须高于通用审美

柚爱本体应更明确区分：

- 通用方法论：shadcn/Tailwind/token/组件状态/反 AI 审美。
- 项目事实：框架、shadcn style、默认明暗优先级、业务密度、当前阶段目标。

建议在 Skill 中增加硬性检查：

```text
动手前必须回答：
1. 当前项目约束档案路径是什么？
2. 当前 shadcn style / baseColor 是什么？
3. 当前默认验收模式是 light、dark 还是 system？
4. 当前 UI 问题应优先通过 token、组件变体还是页面局部 class 解决？
5. 哪些设计文档是历史实验，不能当当前方向？
```

## 2. shadcn 风格应优先走语义 token

mdtest 中出现过一个问题：为了让边框明显，直接新增 `shadow-panel` / `shadow-control` 这类项目外视觉层，结果偏离 shadcn-svelte `new-york` 的克制语言。

可沉淀为柚爱通用规则：

- 先调 `--border`、`--input`、`--ring`、`--accent` 等语义 token。
- 再调 shadcn 组件变体，例如 `Button` / `Card` / `Input`。
- 最后才在页面局部加 class。
- 不应因为一个页面问题新增全局视觉体系。

## 3. 明确“默认验收面”

不同项目默认验收面不同：

- SaaS 控制台可能是浅色。
- 开发者工具可能是深色。
- 游戏或展示页可能需要强视觉。
- 测试工具可能更重视长时间可读性。

柚爱不应默认“暗色高级”或“浅色干净”。应先从项目档案读取默认验收面。

mdtest 当前结论：

```text
默认浅色优先，深色可用，其他风格包是扩展示例。
```

## 4. 历史实验必须降级

项目里会有主题实验、旧布局、旧技术栈迁移记录。柚爱读取文档时需要识别文档状态：

- 当前有效
- 参考
- 历史实验
- 已废弃

建议柚爱本体要求项目提供一个设计目录索引，例如：

```text
docs/design/pomelosuki/README.md
```

里面标明每个文档状态，避免 Agent 把历史实验当成当前方向。

## 5. UI 修改前先做“问题类型判断”

同样是“边框不明显”，解决路径可能完全不同：

| 问题类型 | 优先策略 |
|----------|----------|
| 全局 token 太淡 | 调整 `--border` / `--input` |
| shadcn 组件状态弱 | 调整 `Button` / `Card` / `Input` 变体 |
| 页面信息层级乱 | 调整布局、分组、标题和间距 |
| 某个列表 hover 不清楚 | 局部状态样式 |
| 风格不符合项目 | 回到 project-profile，而不是继续加效果 |

这张判断表可以加入柚爱 Skill 的设计评审流程。

## 6. 复杂项目要避免“一次性定死风格”

柚爱是 Agent，不是某个项目的固定设计系统。建议 Skill 文案更强调：

- 柚爱可服务不同产品类型。
- 每个项目必须有独立 project-profile。
- 项目 profile 可以随阶段变化更新。
- 历史阶段不能自动覆盖当前阶段。

## 7. 对 mdtest 的直接教训

mdtest 这次最有价值的经验：

```text
不要把“增加可见度”直接等价为“加重阴影”。
先确认设计系统，再按 token -> component -> page 的顺序修。
```

这条可以作为柚爱处理 shadcn 项目时的默认排错顺序。

## 8. 不要把“功能完整”误判成“按钮全展示”

mdtest 文件工作台暴露出第二个问题：工具栏把新建文件、文件夹、复制、剪切、粘贴、重命名、删除全部摊开，结果功能看似完整，但界面变得拥挤、缺少优先级。

可沉淀为柚爱通用规则：

- 高频导航动作可以常驻，例如上级、刷新、上传。
- 低频或依赖选择态的动作优先进入右键菜单或更多菜单。
- 新建类操作适合一个入口，再在弹窗或下拉里细分文件夹、空白文件、常用文件类型。
- 工具栏按钮数量不是能力证明；按钮越多，越需要证明它们确实应该常驻。

## 9. 文件管理器的面包屑是主导航，不是辅助说明

文件管理器中，路径定位和返回上级是核心任务。面包屑如果字号太小、颜色太灰、被工具按钮挤在角落，会直接降低可用性。

建议柚爱在设计文件管理器时默认检查：

- 面包屑是否处于文件列表上方的稳定位置。
- 当前路径最后一段是否比历史路径更突出。
- 每段路径是否有足够点击面积。
- 根路径、应用目录、设备根目录等概念是否清晰区分。

## 10. 避免卡片套卡片制造假层级

mdtest 的文件工作台原本放在环境管理页的大卡片里，文件管理器内部又自带一层卡片边框，视觉上形成“框套框”。这种层级并没有表达新的信息，只是增加噪音。

可沉淀为通用规则：

- 如果父容器已经是工作台主面板，子工具应直接占满工作区。
- 卡片用于重复项、独立信息块、弹窗和真正可被框定的工具，不用于给每一层布局都加边框。
- 层级优先用布局分区、标题、间距、背景轻微差异表达；边框只是最后一层辅助。
