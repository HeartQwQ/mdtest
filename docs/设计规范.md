# mdtest 项目设计规范

> 本文件是 mdtest 在 `docs/` 中唯一的 UI/UX 设计事实源。柚爱（pomelosuki）负责通用设计方法和角色分工；本文件只记录 mdtest 项目的框架、路径、主题、布局、边界和验证口径。

## 读取顺序

涉及 UI、主题、组件、布局或视觉评审时，按顺序读取：

1. `Agent/skills/pomelosuki/SKILL.md`：柚爱的通用 shadcn + Tailwind 设计方法。
2. `docs/设计规范.md`：mdtest 项目设计约束，也就是本文件。
3. `docs/需求文档.md`：产品目标、阶段范围和验收标准。

柚爱不是 mdtest 的固定审美；项目风格以本文件为准。

## UI 栈

| 项 | 值 |
|----|----|
| 应用形态 | Electron 桌面端（electron-vite） |
| 渲染框架 | Svelte 5（`$state` / `$derived` / `$props` / `$effect`） |
| UI 原语 | shadcn-svelte（`new-york` / `zinc`）+ `bits-ui` |
| 样式 | Tailwind CSS 4 + `tailwind-variants` |
| 图标 | `@lucide/svelte`，统一 `size-4` / `size-5`，禁止 emoji 作图标 |
| 主题切换 | `mode-watcher` 控制 `.dark`，`data-theme` 控制风格包 |

关键路径：

| 区域 | 路径 |
|------|------|
| 渲染入口 | `src/renderer/src/main.ts`、`src/renderer/src/App.svelte` |
| 页面视图 | `src/renderer/src/lib/views/` |
| 主导航 | `src/renderer/src/lib/components/nav/` |
| 文件工作台 | `src/renderer/src/lib/components/file-explorer/FileExplorer.svelte` |
| shadcn 组件 | `src/renderer/src/lib/components/ui/**` |
| token / 样式 | `src/renderer/src/app.css` |
| 主题状态 | `src/renderer/src/lib/stores/theme.svelte.ts` |

## 当前方向

mdtest 是面向《和平精英》测试团队的 Android-first 测试环境管理工作台，不是营销页、泛 SaaS 控制台或多游戏平台。

- 默认浅色优先，深色保持可用。
- 高密度、可扫描、边界清晰，适合长时间测试工作。
- 使用 shadcn-svelte `new-york`、语义 token 和 lucide 线性图标。
- 四端顺序固定为 PC -> Android -> iOS -> Harmony。
- 投屏 / 画面控制与文件工作台都是核心体验。

## 布局约束

```text
Titlebar
┌───────┬──────────────────────────────────────────────┐
│ nav   │ HomeView / DeviceManagementView / SettingsView│
│ w-14  │                                              │
└───────┴──────────────────────────────────────────────┘
```

环境管理页：

| 区域 | 约束 | 内容 |
|------|------|------|
| 左侧主导航 | `w-14` | icon-only + tooltip |
| 顶部环境栏 | `h-16` | 四端切换、设备选择、投屏/文件模式切换 |
| 中央工作台 | `flex-1` | 投屏或文件工作台直接占满，不再套第二层卡片 |
| 右侧辅助区 | `w-80` | 当前环境、快捷操作、日志/用例进度、AI 辅助入口 |

文件工作台交互约束：

- 四端切换保持一级可见，不放进二级菜单。
- 投屏 / 文件管理属于功能模式，放在环境栏右侧。
- 文件管理器本体不再额外套 `Card`，避免卡片嵌套。
- 工具栏只保留高频入口：目录模式、上级、刷新、上传、新建。
- 新建文件 / 文件夹使用“新建”下拉 + 小浮层确认，不常驻输入框。
- 复制、剪切、粘贴、重命名、删除默认收进右键菜单。
- 面包屑是文件管理器一级导航，必须比普通辅助文本更醒目。
- 根路径通过面包屑首项返回，不额外放无意义“主页”按钮。

Android 文件管理默认对应“设备 / 内部存储”，底层路径优先 `/storage/emulated/0`。UI 展示应从“设备名 / 内部存储 / 子目录”开始，例如：

```text
HONOR 80 GT / 内部存储 / Android / data / com.tencent.tmgp.pubgmhd
```

不要在 mdtest 自身面包屑里硬套 Windows 资源管理器的“此电脑”。

## 主题与 Token

组件必须依赖语义 token，例如 `bg-background`、`text-foreground`、`border-border`、`bg-primary`、`focus-visible:ring-ring`，避免硬编码 `zinc-*` / `cyan-*`。

主题有两个维度：

- 明暗模式：由 `mode-watcher` 在 `<html>` 上切换 `.dark`。
- 风格包：由 `<html data-theme="...">` 切换，如 `default`、`studio`、`cyber`、`forge`。

当前验收优先级：默认浅色 > 默认深色 > 其他风格包。`studio`、`cyber`、`forge` 只作为扩展示例，不代表当前产品主视觉。

新增主题步骤：

1. 在 `src/renderer/src/lib/stores/theme.svelte.ts` 的 `themePalettes` 中增加一项，`id` 即 `data-theme` 值。
2. 在 `src/renderer/src/app.css` 中增加 `[data-theme="id"]` 和 `.dark[data-theme="id"]` 两组变量。
3. 至少覆盖 `background`、`foreground`、`card`、`primary`、`secondary`、`muted`、`accent`、`destructive`、`border`、`input`、`ring`、`sidebar*`。
4. 不改业务组件，除非该组件之前硬编码了颜色。

## 柚爱边界

柚爱可设计和改造：

- 页面布局、视觉层级、信息密度。
- shadcn-svelte 组件组合和状态样式。
- Tailwind 语义 class 与 `app.css` token。
- 明暗模式、主题变量、hover、focus-visible、disabled、empty、loading、error 状态。

柚爱不直接决定：

- Electron main / preload / IPC 权限模型。
- adb / hdc / libimobiledevice 调用策略。
- 文件删除、写入、备份、恢复等高风险业务规则。
- AI 自动化执行、OCR、图像识别模型和测试用例生成逻辑。

## 验收

修改 UI 后运行：

```bash
pnpm run verify
```

只改文档时可以不运行构建，但完成报告必须说明。涉及视觉质量时，默认先检查浅色模式，再检查深色模式是否可用。
